# Working on Farm Village

These rules are for every coding agent working in this repository (Codex, Claude Code or any other). Read them before
you start a task.

Farm Village is a single-player cozy farm and village game for phones and PC browsers (Three.js, shown like 2.5D). The
player brings the run-down village of Hollowbrook (*Thung Suối*) back to life. The game is in English and Vietnamese.

**Read first**
- `docs/JOURNEY.md`: the eight stages, the story acts and the build order.
- `docs/STORY.md`: the cast, how each person talks, and the Vietnamese pronoun rules.
- `docs/RESEARCH-APPEAL.md`: what makes the game fun alone, the colour and gold rules, interaction ideas and the ranked
  suggestions.
- `docs/ASSET-REQUESTS.md`: the queue between the two lanes, and the models and icons you can already use.
- `CHANGELOG.md`: what changed lately.

## 1. Two lanes

Two agents work in parallel. Each owns its own files, so they do not overwrite each other.

| Lane | Usually | Owns |
|---|---|---|
| **Art** | Claude Code | `art/blender/**`, `public/assets/models/**`, `public/assets/icons/**`, story pictures in `public/assets/story/**`, `docs/ASSETS.md`, `docs/ASSET-REQUESTS.md` (deliveries), and the **look** (see below) |
| **Logic** | Codex | Everything else: `src/core/**`, `src/content/**`, `src/ui/**`, `src/i18n/**`, `scripts/**`, `tests/**`, story text, Vietnamese lines, economy and pace |

**The look** belongs to the art lane: colour and light values and how effects look. That is `GROUND_COLORS` in
`src/view/world-view.mjs`, the lights and toon ramp in `src/kit/toon.mjs`, the day and night palettes in
`src/view/daylight.mjs`, the colour tokens in `src/style.css`, and the colours, sizes and timing of particles and
celebrations in `src/view/juice.mjs`, `src/ui/fx.mjs` and `src/view/marks-view.mjs`. The logic lane may call effects
(emit events, call the existing effect functions) but leaves their look to the art lane.

**Shared files**, and how each lane touches them:
- `src/view/kinds.mjs`: the art lane writes the real model entries. The logic lane may add a **stand-in** line for a new
  kind that points at an existing model, with a comment such as `// stand-in for AR-012`. The `ANCHORS` block is
  generated by `art/blender/anchors.mjs`: never edit it by hand.
- `src/content/icons.mjs`: the art lane adds icon ids. The logic lane may add an id only together with a placeholder
  icon (section 3).
- The rest of `src/view/**` is shared: the logic lane owns behaviour (who walks where, what a tap does), the art lane
  owns looks and purely visual modules (for example `src/view/pond-fish.mjs`). Keep edits small; before a big change,
  write a note in `docs/ASSET-REQUESTS.md` ("Notes between lanes") and tell the user.
- `CHANGELOG.md`, `PROGRESS.md`, the status table in `docs/JOURNEY.md`: both lanes add their own lines; never rewrite
  the other lane's lines.

If the user moves a task from one lane to the other, follow the user and update this table.

## 2. Branches, worktrees and pull requests

- **Logic lane:** branches named `codex/<topic>`, in the main checkout of the repository.
- **Art lane:** branches named `art/<topic>`, in a separate worktree next to the main checkout (`../Farm_village-art`).
- Every change reaches `main` through a pull request. `.github/workflows/checks.yml` (added with the v0.4 pull request)
  runs `npm test` and the build on pull requests. **Merging into `main` deploys the live game** (`.github/workflows/pages.yml`), so merge only when the
  user says so and every test passes.
- Before you start a piece of work, and again before you open a pull request, merge the latest `origin/main` into your
  branch.
- Never commit in the other lane's checkout, and never push to or rewrite the other lane's branch.

## 3. Binary files have one writer

Git cannot merge binary files. GLB models, WebP icons and story pictures are written only by the art lane.

- `public/assets/models/farm-kit.glb` and `decor.glb` are build outputs of `art/blender/build_farm_kit.py`. Never edit
  them by hand. After a change to that script is merged, the art lane rebuilds and packs them.
- **Placeholder icons (the one exception).** Every good, building and tool needs an icon file
  (`tests/assets.test.mjs`). If the logic lane cannot wait for one, it may copy an existing icon to the new id's file
  name (for example `bread.webp` to `jam_cherry.webp`), add the id to `src/content/icons.mjs`, and log it in
  `docs/ASSET-REQUESTS.md` with the status `placeholder`. The art lane replaces it. Before it does, it merges the branch
  that added the placeholder, so the replacement is an ordinary change and not a conflict.

## 4. Stand-ins: the logic lane never waits for art

Use what already exists (the stock list in `docs/ASSET-REQUESTS.md`), file a request, and carry on. When the real model
or icon lands, the art lane switches the stand-in line in the same pull request, and the logic lane checks it in play.

## 5. House rules for code

- **Rules** live in `src/core` behind `act(state, action, payload, now)` and `tick(state, now)`. A handler checks
  everything before it changes anything, so a refused action leaves no trace. **Content** is data in `src/content`.
  Drawing is in `src/view`, the interface in `src/ui`, saves in `src/kit/save.mjs`.
- **Vietnamese:** every string on screen (`t()`, `ctx.fail()`, content text) needs a line in `src/i18n`. Tests check
  coverage and placeholders. Each speaker keeps the pronouns in `docs/STORY.md` section 2 (`tests/story.test.mjs`).
- **Cozy rules:** nothing is lost, wilts, spoils or leaves while the player is away; no energy bars, no paid currency;
  no lines that make the player feel guilty for being away; pets and animals never suffer if ignored
  (`docs/RESEARCH-APPEAL.md` section 7).
- **Pace:** `npm run sim` and `tests/sim.test.mjs` must stay green.
- **Phone budgets:** at most 120 draw calls and 300,000 triangles at every zoom; first-load code at most 1.1 MB (the
  build prints it). Triangle caps per model are in `tests/assets.test.mjs`.
- **Tests for every feature:** rules tests (`tests/*.test.mjs`) and a browser check (`tests/*.browser.mjs`).
- **How to test:** `npm test`, then `npm run build:test`, then serve `dist` with `node scripts/serve-dist.mjs <port>` and
  run `GAME_URL=http://127.0.0.1:<port>/ node scripts/run-browser-suites.mjs` and `node tests/browser.mjs`.
  - Ports: the logic lane uses **5241**, the art lane **5242**. Other projects on this machine use other ports (4173,
    4197, 5178, 5184, 5207, 5251, 5262, 5321): do not use those.
  - Stop a server you started by its process id, never by process name: other sessions run servers too.
  - Tests pin the time zone to Asia/Seoul (`tests/tz.mjs`); CI runs in UTC.
- **When a task is done:** add lines to `CHANGELOG.md` and update the status in `docs/JOURNEY.md`.

## 6. Art lane tools

- Blender 4.5.9, run headless with a portable copy (never a Blender window or session that is already open):
  `blender --background --factory-startup --python art/blender/build_farm_kit.py`.
- Icons: `blender -b --factory-startup --python art/blender/render_icons.py -- <ids>`, with jobs listed in
  `art/blender/icons.json`.
- Packing: `node art/blender/pack.mjs <in.glb> <out.glb>` (meshopt; `tests/assets.test.mjs` checks every kit is packed).
- Record where every asset comes from in `docs/ASSETS.md`. Reuse from the user's own earlier games is fine; take only
  patterns, never art, from other people's games.

## 7. Talking to each other

- Asset needs: `docs/ASSET-REQUESTS.md` (the template is there).
- Anything else between lanes (a big change to a shared file, a rule you want changed): a dated line in "Notes between
  lanes" at the end of `docs/ASSET-REQUESTS.md`, and tell the user.
- Questions only the user can answer: ask the user.
